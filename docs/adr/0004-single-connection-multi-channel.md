# ADR 0004：一条连接承载全部频道

- 状态：已采纳
- 日期：2026-11-16

## 背景

房间里有多个频道。两种实现：每个频道一条 `RTCPeerConnection`（或 DataChannel），
还是所有频道共用一条连接、在应用层做分区。

## 决策

每个对端**一条** `RTCPeerConnection` + **一条** `DataChannel('tu-bubbles')`；
频道只作为消息的 `channelId` 分区（以及本地订阅过滤）。

## 后果

- 切频道只改本地 `activeChannelId`，不重连、不重新握手，切换是瞬时的；
- 连接数 = 成员数，内存与握手开销最小；SDP 交换次数也少；
- `channels` 列表、`nickname`、`ack` 这些控制消息与聊天消息共用一条流，需要靠 `t` 字段区分；
- 没有「只订阅某个频道」的服务端语义——所有人都收到所有频道的消息，
  由接收端决定是否落库/显示（当前策略：**全部落库**，只在 UI 上按频道过滤）。

## 备选

- 每频道一条 DataChannel：频道多时连接/通道数膨胀，断线重连要处理 N 条，复杂且收益低。
- 频道级订阅过滤：会在「切回频道看不到历史」上出问题，与「重启后仍可读取」冲突。
