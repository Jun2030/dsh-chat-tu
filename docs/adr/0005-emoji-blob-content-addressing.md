# ADR 0005：自定义表情以 BLOB 存库、内容哈希去重

- 状态：已采纳
- 日期：2026-11-16

## 背景

需求：表情支持自定义与上传。要决定图片存哪、怎么发给对端、怎么去重。

## 决策

- 图片字节存 SQLite `emojis.bytes`（BLOB），限制 PNG/GIF/WebP ≤ 256 KiB；
- id = `e-<sha256(bytes) 前 16 位>`：**内容寻址**，同一张图重复上传、对端落地都得到同一个 id；
- 列表接口只回元数据，显示时按需 `emojis/get`（base64）；
- 发送自定义表情时，图片字节随消息信封一起经 DataChannel 发出，对端收到后立刻落库。
  消息 `body` 里只存 `{emojiId, name}`，不重复存图片。

## 后果

- 不依赖任何图床/网络存储，离线可用，删库即删干净；
- 去重是天然的：双端各自 `INSERT OR IGNORE`，id 相同不会重复；
- 对端即使之前没这个表情，收到消息也能立刻看到（图片随消息而来）；
- 代价：图片会在 DataChannel 上多传一次；256 KiB 上限保证不会把连接拖垮；
- 历史消息引用的表情如果被本地删除，UI 会退化成「未找到该表情」的占位，不报错。

## 备选

- 只存 URL：需要图床，不满足本地/离线要求；
- 存文件系统：要自己管理目录与清理，BLOB 在这个量级更简单；
- base64 存 TEXT：体积膨胀 33%，且没有内容寻址的便利。
